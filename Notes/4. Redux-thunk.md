
# Modern API call state management.

- In modern React apps using Redux Toolkit, 
- there are 3 common ways to call APIs:
```
    useEffect + fetch/axios
    createAsyncThunk
    RTK Query (useQuery) ✅
```
- Problem with this approach
- If many components call APIs separately:

```
❌ Duplicate API calls
❌ Repeated loading/error state logic
❌ No shared cache
❌ Harder state management
❌ Difficult to scale
```
#### Imagine:

- Navbar needs user data
- Profile page needs user data
- Dashboard needs user data

All 3 may call the same API again.



### 2️⃣ createAsyncThunk

createAsyncThunk is used when:

- You want API data stored in Redux global state
- Multiple components share the same data
- You want centralized loading/error handling
- You need custom business logic

###Example:

```
export const fetchUsers = createAsyncThunk(
  'users/fetchUsers',
  async () => {
    const res = await fetch('/api/users')
    return res.json()
  }
)
```

Then reducers handle:
```
extraReducers: (builder) => {
  builder
    .addCase(fetchUsers.pending, (state) => {
      state.loading = true
    })
    .addCase(fetchUsers.fulfilled, (state, action) => {
      state.loading = false
      state.users = action.payload
    })
}
```

# Why people use it

#### Because:

- Redux store becomes single source of truth
- Easy to share data across app
- Good for complex workflows
